这个版本让应用可以同时登记多个视频服务器，当前服务器出问题时，会自动换到下一个。v1.9 的经历说明，只依赖一个公共服务器太脆弱：它一封锁或者一宕机，整个应用就一首歌也下不了。

现在投影仪版和平板版都会保存一份服务器列表。当前服务器连不上、返回 429（请求太多）或返回 5xx 错误时，应用会自动切换到列表里的下一个服务器。一个服务器出过问题后，10 分钟内不会再切回它；切换后的 30 秒内，还在路上的旧请求报的错不会再触发切换，避免在几个服务器之间来回乱跳。如果列表里所有服务器都有问题，就按 v1.9 的方式让所有下载一起暂停等待。切换服务器时不会清空歌单，也不会重新下载已经存好的部分：缓存是按视频格式编号、文件大小和文件版本来识别文件的，跟文件是从哪个服务器下来的无关，所以换了服务器以后，下了一半的文件能接着下。

平板的家长设置里新增了「视频服务器」一栏，可以看到正在用的是哪个，手动切换或者删除。添加新服务器时，应用会先实测它能不能取到频道信息和播放清单，不能用的不会加进列表，免得填了一个坏地址，反而让自动切换更频繁。

不过这个功能做好时，其实没有可以换的服务器。开发它的同时，我们找了一圈备用方案，结果都不能用。公开的 Invidious 服务器试了大约 20 个，没有一个能完整使用：多数返回 403 拒绝访问、连接超时或者关闭了接口，有一个能取到频道列表，但拿不到播放清单。另一类同类服务 Piped 的公开服务器，也都返回 500 或 502 错误。我们还试了用 yt-dlp 直接从 YouTube 下载：普通视频能解析，但儿歌这类被 YouTube 标记为「面向儿童」的内容，会直接提示「视频不可用」。原因是 YouTube 现在要求这类请求附带一种叫 PO Token 的校验凭证，普通的下载工具拿不到。

所以这个版本完成时，列表里实际只有一个服务器。真正解决问题的是 v2.2：在家里电脑上自建一个私有服务器。
