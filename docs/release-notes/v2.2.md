这个版本让平板版用上了自建的私有 Invidious 服务器，并在家长设置里加入了服务器测速。为了把它真正用起来，还连续修了四个问题：平板连不上服务器、能用的服务器被自动换掉、私有服务器速度上不去，以及很多歌被误判为没有字幕。

v1.9 和 v2.1 的经历说明，公共服务器靠不住，所以我们在家里那台给平板开热点的电脑上，自己搭了一个只给自己用的 Invidious。它由三个容器组成。`invidious` 负责提供歌单、播放清单和字幕。`invidious-companion` 负责直接和 YouTube 打交道，它能自己生成 YouTube 要求的 PO Token 校验凭证，所以 v2.1 里拿不到的儿童内容，它也能正常取到。`postgres` 是 Invidious 要用的数据库。三个容器用 podman 运行，交给 systemd 管理，开机后自动启动；`podman auto-update` 每天检查一次镜像更新，因为 YouTube 经常改规则，companion 需要跟着更新。服务器只监听电脑热点的地址，只有连着这个热点的设备能访问，家里其他网络和外网都访问不到。如果你也想自己搭，要注意两个配置：companion 的 `public_url` 必须填平板能访问到的地址（热点 IP 加 8282 端口），否则播放清单里的视频地址平板打不开；`invidious_companion_key` 在两边必须一致，长度为 16 位。

平板版现在默认使用这个私有服务器，原来的公共服务器留在列表里作为备用。因为家里内网的私有服务器一般没有 https，应用现在也允许访问 `http://` 地址。

家长设置的「视频服务器」一栏，每个服务器旁边多了一个「测速」按钮。测速时先取一次频道信息，测服务器的响应时间；再取一首已存歌曲的播放清单，实际下载 4 MB 画面，测下载速度。一共只发 3 个请求，不会给服务器添加负担。「全部测速，选最快的」会把列表里的服务器逐个测一遍（不同时测），然后自动切换到下载最快的那个。

第一个问题是平板提示连不上私有服务器。服务器在电脑上运行正常，平板也能 ping 通电脑，可应用就是连不上。原因在电脑的防火墙：它给热点网络只放行了 DHCP、DNS、SSH 和 ping，其他端口一律拒绝。在热点所在的防火墙区域放行服务器用的 3000 和 8282 两个端口后，就连上了。

第二个问题是能用的私有服务器被自动换掉了。日志显示，应用以「私有服务器出问题」为由切到了公共服务器，可报错内容其实是连不上公共服务器。原来是切换服务器的那一刻，还有一批发往旧服务器的请求在路上，它们失败后报的错，被记到了新服务器的头上。现在应用会先看报错里提到的是哪个服务器：如果是别的服务器，就不算当前服务器的错。

第三个问题是私有服务器只跑出约 8 MB/s。查看服务器日志发现，每分钟只处理了 30 个左右的播放清单请求，而且要和补字幕的请求轮流排队，下载任务大部分时间都在等清单。原因是 v1.9 为保护公共服务器加的「一次一个请求、间隔 0.7 秒」的限制，原样套在了我们自己的服务器上。私有服务器只给我们用，没有必要这么克制。现在发往私有服务器的请求最多可以同时 8 个，不再间隔；公共服务器仍然一次一个。改完后实测下载速度 58 MB/s。

第四个问题是很多歌被误判为没有字幕。v2.0 只按频道语言找字幕，所以英文频道的歌即使带有简体中文字幕，也会被记成「没有字幕」。抽查时就发现过一首带简体中文字幕、一首带英文自动字幕的歌，都被标成了没有字幕。现在的规则是：先找频道语言的字幕，没有就找中文，再没有就找英文；同一种语言里，人工字幕优先于自动生成的字幕。之前被标成「没有字幕」的歌，会全部重新查一遍。改完后，已经查过的歌里大约三分之一有字幕；剩下的歌抽查确实一条字幕都没有，儿歌视频常常这样。

还有两个已知问题。少数歌曲 companion 只能通过 YouTube 的备用通道取到，这时 H.264 格式最高只有 480p，720p 以上只有 AV1 格式；而多数平板没有 AV1 的硬件解码，所以这些歌会存成 480p。另外，私有服务器要靠家里的电脑开着才能用；带出门以后，平板只播放已经存好的歌，本来也不需要它。
